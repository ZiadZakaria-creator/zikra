# تجهيز Firebase للوحة التحكم

المشروع: `zikra-20e55`. الخطوات دي بتتعمل مرة واحدة من Firebase Console.

## 1. قواعد الأمان
1. Firestore Database ← تبويب **Rules**.
2. امسح اللي موجود، والصق محتوى ملف [`firestore.rules`](../firestore.rules) كله.
3. دوس **Publish**.

القواعد دي متجربة بـ 31 اختبار (`tests/rules.test.mjs`): الزائر يقدر يعمل أوردر بس، وبعد ما القواعد تتأكد من الشحن والإجمالي وكود الخصم. الأدمن بس هو اللي يشوف الطلبات ويعدّل.

## 2. حسابات الأدمن (لكل واحد من الـ 3)
1. **Authentication** ← **Users** ← **Add user**: الإيميل وباسورد قوي.
2. انسخ الـ **User UID** اللي هيظهر جنب الإيميل.
3. **Firestore Database** ← **Data** ← **Start collection** (أول مرة) واكتب `admins`.
   - **Document ID**: الصق الـ UID.
   - ضيف field اسمه `email` (string) واكتب الإيميل.
4. كرر للأدمن التاني والتالت (من **Add document** جوه `admins`).

اختياري ومستحسن: **Authentication** ← **Settings** ← **User actions** ← شيل علامة **Enable create (sign-up)**، علشان محدش يعمل حسابات من بره.

## 3. أول دخول
1. افتح `https://ziadzakaria-creator.github.io/zikra/admin/`
2. ادخل بإيميل وباسورد أدمن.
3. **المنتجات** ← **استورد العطور الحالية من الموقع** (مرة واحدة). ده بينقل الـ 7 عطور وإعدادات الشحن لقاعدة البيانات.
4. **الشحن والإعدادات**: راجع الأرقام والأسعار ودوس **احفظ الإعدادات**.

## مهم
- الطلبات بتوصل اللوحة على طول.
- تعديلات المنتجات والأسعار والشحن بتظهر على الموقع بعد النشر (مرحلة د بتعمل النشر ده أوتوماتيك).
- لو غيّرت سعر الشحن ولسه الموقع مااتنشرش، قواعد الأمان هترفض الطلب لأن السعر مختلف. العميل وقتها بيتقاله يبعت الطلب على واتساب، فالطلب مش بيضيع، بس مش هيظهر في اللوحة.

## تشغيل الاختبارات
```bash
cd tests && npm install && npm run rules
```
